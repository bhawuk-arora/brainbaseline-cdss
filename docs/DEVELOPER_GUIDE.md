# 🛠️ BrainBaseline: Developer Guide & Engineering Handbook

Welcome to the BrainBaseline engineering codebase. This document serves as the onboarding manual for developers, clinical informaticians, and data engineers extending or maintaining the platform.

---

## 1. Architectural Philosophy & Zero-Hallucination Invariant

In conventional healthcare software, machine learning or LLMs are often incorrectly tasked with making diagnostic decisions. In BrainBaseline, **the system follows a zero-hallucination invariant**:

1. **Math Is Pure & Deterministic:** All statistical scoring (Robust Z, Reliable Change Index, CUSUM drift, and empirical Bayes shrinkage) is implemented in pure Python with NumPy. There are no stochastic weights or random seeds at inference time.
2. **LLM Never Triages:** Triage colors (`green`, `yellow`, `orange`, `red`, `baseline`) are computed via rule priority in `packages/engine/triage.py`.
3. **Guardrailed Natural Language:** Explanations delivered to patients are generated by bilingual deterministic templates in `packages/explain/templates.py`, verified against a strict banned-word filter (`packages/explain/guardrails.py`) that blocks diagnostic assertions.

## 3. How Data Flows End-to-End

When a user completes a check at `/check`:

```
1. Frontend Interaction:
   User completes Task 1 (Word Memory), Task 2 (Sequence Studio), and Task 3 (Go/No-Go).
   Scores and sub-metrics are collected in React State.

2. Submission Payload:
   POST /api/sessions/{session_id}/results
   Payload contains:
   {
     "user_id": "user_layla",
     "scores": {"memory": 9.5, "sequence_av": 9.0, "attention_rt": 47.0},
     "sub_metrics": {"visual_acc": 0.85, "auditory_acc": 0.80, "median_rt_ms": 420},
     "context": {"sleep_hours": 7.0, "mood_positive": false, "illness": false, "new_medication": false},
     "red_flags": {"sudden_confusion": false, "speech_trouble": false, ...},
     "function_items": [1, 1, 1, 1, 0, 0, 0, 0]
   }

3. FastAPI & Orchestrator Execution:
   • Gate 1: Confirms active consent.
   • Gate 2: Checks for red flags.
   • Gate 3: Flags context confounding (e.g., sleep < 5h).
   • Gate 4: Retrieves historical sessions from SQLite (WAL mode);
             computes robust z-scores against personal baseline;
             updates CUSUM drift state; evaluates triage rules.
   • Gate 5: If triage is Orange or Red, sets `held_for_review = True` and
             inserts a pending `Review` record with `released_at = None`.

4. Participant Disclosure Guard:
   When participant calls GET /api/users/{id}/result:
   If `held_for_review == True` and `released_at is None`:
     Returns status: "pending_clinician_review" with calm holding text.
     Never reveals raw z-score or Orange/Red alert.

5. Clinician Action:
   Clinician inspects GET /api/review/queue on /clinician.
   Reviews trend SVG chart and Reversible-Cause checklist.
   Submits POST /api/review/{triage_id}/decision.
   Sets `released_at = now()`.
   Participant's /result endpoint automatically unlocks with finalized clinical guidance!
```

## 4. How to Add a New Cognitive Task

1. **Define Population Parameters in `data/triage_rules.json`:**
   ```json
   "domains": {
     "your_new_task": {
       "pop_mean": 50.0,
       "pop_sd": 10.0,
       "reliability": 0.84,
       "safety_floor": 20.0
     }
   }
   ```
2. **Add Scoring Function in `packages/engine/scoring.py`:**
   Create a pure function that normalizes raw interaction data to the task scale.
3. **Create the React Component in `apps/web/src/components/tasks/`:**
   Follow the pattern of `WordMemoryTask.tsx` or `SequenceStudioTask.tsx`:
   * Include `"use client";` at line 1.
   * Provide Web Speech / Web Audio synthesis where applicable.
   * Guard all browser APIs with `typeof window !== "undefined"`.
   * Emit `onComplete(score, subMetrics)`.
4. **Wire into `apps/web/src/app/check/page.tsx`:**
   Add a step in the task carousel and pass the score in the final submission.

## 5. How to Add a New Reversible Cause

1. Add the item in `data/triage_rules.json` under `reversible_causes`:
   ```json
   {"id": "rc7", "en": "Renal or hepatic electrolyte imbalance", "ar": "اضطراب وظائف الكلى أو الأملاح"}
   ```
2. The item is automatically loaded by `/api/review/queue` and rendered as an interactive checkbox in `/clinician`.

### 8. Scalable Enterprise ID Conventions & Seeded Cohort

The platform implements unified, scalable hospital identifier prefixes across all models, endpoints, and UI views:

| Role / Entity | Prefix Convention | Example ID | Purpose |
| :--- | :--- | :--- | :--- |
| **Patients & Participants** | `PAT-{HEX}` / `PAT-{NUM}` | `PAT-0042`, `PAT-A91B02` | Standardized outpatient / participant identification. |
| **Licensed Clinicians (Doctors)** | `DOC-{NAME}` / `DOC-{HEX}` | `DOC-NOUR`, `DOC-KHALID` | Attending physician review queue routing. |
| **Hospital Medical Directors** | `DIR-{ENTITY}` | `DIR-DOH`, `DIR-SEHA` | Executive clinical override and SLA governance. |
| **Reception / Admissions Staff** | `REC-{LOCATION}` | `REC-CCAD`, `REC-SEHA` | Front desk intake & MRN issuance tracking. |
| **System Administrators** | `ADM-{ENTITY}` | `ADM-DOH` | Audit inspection, IAM, and synthetic benchmarks. |

The database seeder (`apps/api/seed_patients.py`) generates a diverse cohort of 100+ longitudinal patient records with complete trajectories (Green 60%, Yellow 15%, Baseline 15%, Orange 8%, Red 2%) for stress-testing and clinical validation.

### 9. Reception Desk Admissions & Front Desk Resolver

1. **Intake & Clinician Dispatch**:
   * Outpatients are checked in via `POST /api/reception/checkin`.
   * Automatically assigns an attending specialist (`attending_clinician_id`), generates an institutional MRN (`MRN-CCAD-XXXXXX`), sets up Session #1, and enqueues a baseline review.
2. **Registration Track (`GET /api/reception/registered-patients`)**:
   * Logs every front-desk registration with timestamp, patient name, MRN, insurance, co-pay status, and assigned doctor.
3. **Problem Resolver SOPs**:
   * Front desk standard operating procedures for expired Emirates IDs, Malaffi HIE digital consent, Thiqa 100% co-pay exemptions, shift changes, and Arabic dialect accompaniment.
